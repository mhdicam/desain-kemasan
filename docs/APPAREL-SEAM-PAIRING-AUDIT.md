# Apparel pattern seam-pairing audit (Phase 1)

The repository contains nine **sample draft** apparel .pattern.json files. Every draft has patternPieces (cutContour / stitchContour / cutCount / sheetOffsetMm) and a sewingGraph. However, the older UI displayed only a flat PNG, and no detailed seam-part association was visible.

## Implemented in this PR
- Choose **Pola & Jahitan** in apparel mockup; default view for models with apparelPattern.
- Interactive 2D sheet draws imported cut contours and stitch contours at their original mm offsets, with part labels, cut quantity and seam allowance.
- Relationship cards J01…Jn display source A/B edge strings and method. Selecting a card highlights participating pieces and draws orange **center-to-center** relationship connectors.
- Multi-piece references like `front+back.neckline` and shorthand references like `body.left+bottom+right` are resolved to existing part IDs.
- Unresolved aliases (`visor.base`, `crown.bottom`) are flagged rather than guessed.
- Pure module logic and all nine models covered by test suite in prebuild.

## Not included / cannot be inferred from existing data
Source sewingGraph **does not have measured seam edge segments**, edge endpoints, notch or alignment annotations. The diagram explicitly labels center connectors as schematic; do **not** treat them as edges to sew or a stitch-length match. Physical seamMatching is `NOT_VALIDATED` for all nine source patterns; fit/grading likewise not validated.

## Phase 2 required for manufacturing
For each seam pair define a stable concrete `pieceInstanceId`, `edgeId`, `stitchContour vertex ranges or parameterized edge polylines`, corresponding notch points, direction, target length, ease and seam allowance. Verify both sides within fabric-specific ease tolerances; generate cut layers / notches only after independent physical pattern validation.

No GLB garment model is generated by this change. This is an interactive sewing relationship inspector, not an assembled cloth simulation.
